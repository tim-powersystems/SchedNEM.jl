# SchedNEM.jl model formulation

SchedNEM.jl is an economic dispatch unit commitment (ED-UC) optimisation package in Julia [1], using JuMP [2] and the ParametricOptInterface [3]. It includes a rolling horizon setup and a transport network power flow formulation.

The data structure is built upon the system model formulation in PRAS [4], with additional parameters imported from files generated by PISP.jl. In the following, the detailed underlying model formulation is outlined, as implemented in the code. Implementation remarks are given in `[!NOTE]` blocks; code references are given as `file:line` relative to `src/`.

| --- | --- | --- |
| $\bar{P}^{DRbrw}_{dr,t}$, $\bar{P}^{DRpyb}_{dr,t}$ | Max. borrow/payback power, demand-response $dr$, time $t$ [MW] | `drs_borrow_cap` / `drs_payback_cap` |

> [!NOTE]
> The energy interest $r_{dr}$ is the growth (positive) or shrinkage (negative) of the borrowed energy: the payback needs to exceed the borrowed energy if the interest is positive, and can be less if it is negative. During parameter updates, the interest of all DSP units is set to $r_{dr} = -1$ (`update/updateParameters.jl:122-124`), so DSP borrowing does not accumulate energy that has to be paid back (representing load reduction rather than load shifting); EV units use the interest and energy capacity from the input data (`updateParameters.jl:126-129`).

### 6. Cost parameters

| Symbol | Description | Code name |
| --- | --- | --- |
| $c^{SRMC}_g$ | Short run marginal cost, generator $g$ [\$/MW] | `sys.attrs["cvar_<id>"]` |
| $c^{stup}_g$ / $c^{shdw}_g$ | Startup/shutdown cost, generator $g$ [\$] | `genData.start_up_cost` / `genData.shut_down_cost` |
| $c^{Spen}$ | Penaliser, storage discharging [\$/MW] | `objective_parameters.storage_discharging_price` |
| $c^{GSpen}$ | Penaliser, generator-storage discharging [\$/MW] | `hydro_parameters["hydro_discharging_cost"]` |
| $c^{GSspill}$ | Spillage penalty for generator storage units [\$/MW] | `objective_parameters.spillage_penalty` $\cdot$ `VoLL_min` |
| $c^{GSslack}$ | SoC target violation penalty for generator storage units [\$/MWh] | `objective_parameters.target_slack_penalty` $\cdot$ `VoLL_min` |
| $c^{DRact}_{dr}$ | Activation cost, demand response $dr$ [\$/MW] | `objective_parameters.dsp_rr_cost` $\cdot$ `VoLL_min` (or `sys.attrs["cvar_dr_<id>"]`) |
| $c^{Fpen}$ | Flow penalty across interfaces [\$/MW] | `objective_parameters.transmission_flow_penalty` |
| $VoLL_t$ | Value of Lost Load, time $t$ [\$/MW] | from `sys.attrs["VoLL_max"]` / `sys.attrs["VoLL_min"]` |

The Value of Lost Load decreases linearly over the optimisation window (`model/objective.jl:90`):

$$VoLL_t = VoLL_{max} - \frac{VoLL_{max} - VoLL_{min}}{N-1}\,(t-1)$$

with $VoLL_{min}$ defaulting to $0.99 \cdot VoLL_{max}$. This makes load shedding slightly cheaper later in the window, so that any available storage discharge or demand response is dispatched *greedily*, i.e. as early as possible. A guard errors if $0.99 \cdot VoLL_{min}$ does not exceed the maximum generator SRMC (`objective.jl:56-58`).

All variables are non-negative except $e^{DR}_{dr,t}$, which is free (`model/variables.jl:35`). The interface flow is modelled with two non-negative variables per interface; the net flow is $f^{fwd}_{i,t} - f^{bwd}_{i,t}$. Since the flow penalty is applied to their sum (see objective below), simultaneous flows in both directions are suppressed in the optimum.

## Indices and sets

- $b \in B$ — buses (regions) in the system
- $g \in G$ — generators in the system
- $s \in S$ — storage units in the system
- $gs \in GS$ — generator-storage units in the system
- $dr \in DR$ — demand-response units in the system
- $i \in I^{from}_b, I^{to}_b$ — interfaces from, to bus $b$
- $t \in T = \{1, \ldots, N\}$ — time steps of the optimisation window

> [!NOTE]
> In the code the bus/interface incidence is held in a `connection_matrix` (`model/core.jl:48-52`) with $-1$ at the from-region and $+1$ at the to-region of each interface. Unit-to-region membership comes from the PRAS system (`sys.region_gen_idxs`, `sys.region_stor_idxs`, `sys.region_genstor_idxs`, `sys.region_dr_idxs`).

## Objective function

We define the following costs, which include operational costs and penalties to represent more realistic behaviour.

**Cost functions**

$$C^{gen,op} = \sum_{t \in T} \left( \sum_{g \in G} c^{SRMC}_g\, p_{g,t} + \sum_{g \in G} c^{stup}_g\, \delta^{stup}_{g,t} + \sum_{g \in G} c^{shdw}_g\, \delta^{shdw}_{g,t} \right)$$

$$C^{dem} = \sum_{t \in T} \left( \sum_{dr \in DR} c^{DRact}_{dr}\, p^{DRbrw}_{dr,t} + \sum_{b \in B} VoLL_t\, LS_{b,t} \right)$$

**Penalty functions**

$$C^{stor,op\,pen} = \sum_{t \in T} \left( c^{Spen} \sum_{s \in S} p^{Sdch}_{s,t} + c^{GSpen} \sum_{gs \in GS} p^{GSdch}_{gs,t} \right)$$

$$C^{flow\,pen} = c^{Fpen} \sum_{t \in T} \sum_{i \in I} \left( f^{fwd}_{i,t} + f^{bwd}_{i,t} \right)$$

$$C^{spill\,pen} = \sum_{t \in T} c^{GSspill} \sum_{gs \in GS} s_{gs,t}$$

$$C^{slack\,pen} = c^{GSslack} \sum_{gs \in GS} e^{slack}_{gs}$$

Which are combined to the overall objective function:

$$\min \; C^{gen,op} + C^{dem} + C^{stor,op\,pen} + C^{flow\,pen} + C^{spill\,pen} + C^{slack\,pen} \tag{1}$$

Implemented in `model/objective.jl:96-99` (expressions built at `objective.jl:74-93`). The startup/shutdown cost terms are only included when UC is enabled.

With the default parameters of:

- $c^{Spen}$: 0.1 \$/MW — Small penalty to avoid degeneracies in cases with high curtailment, to prevent unrealistic storage cycling for minimal cost benefits.
- $c^{GSpen}$: 8.58 \$/MW — SRMC of hydro from ISP24. Used here to represent the value of water in future timesteps.
- $c^{Fpen}$: 0.1 \$/MW — Small penalty to contain ENS within primary subregion. Furthermore, this helps preventing excessive storage operation across regions for minimal cost benefits, and suppresses simultaneous forward and backward flows on the same interface.
- $c^{GSspill}$: 0.80 $VoLL_{min}$ \$/MWh — High penalty of spillage to incentivise keeping water within the reservoirs/dams.
- $c^{GSslack}$: 0.80 $VoLL_{min}$ \$/MWh — High penalty of violating final SoC target to incentivise keeping water within the reservoirs/dams.
- $c^{DRact}_{dr}$: 0.95 $VoLL_{min}$ \$/MWh — High cost of demand response for all units that are in the reliability response price band, as well as for EV disconnection.

> [!NOTE]
> The DR activation cost defaults to $0.95 \cdot VoLL_{min}$ for **all** DR units; a per-unit cost from `sys.attrs["cvar_dr_<id>"]` is used only if it is *lower* than the default (`objective.jl:65-70`).

## Constraints

### Power balance

Nodal power balance for each bus $b$ and time $t$ (`model/constraints.jl:18-29`, JuMP name `powerBalance`):

$$\sum_{g \in G_b} p_{g,t} - \sum_{i \in I^{from}_b} \left( f^{fwd}_{i,t} - f^{bwd}_{i,t} \right) + \sum_{i \in I^{to}_b} \left( f^{fwd}_{i,t} - f^{bwd}_{i,t} \right) + \sum_{s \in S_b} p^{Sdch}_{s,t} + \sum_{gs \in GS_b} p^{GSdch}_{gs,t} + \sum_{dr \in DR_b} p^{DRbrw}_{dr,t} - \sum_{s \in S_b} p^{Sch}_{s,t} - \sum_{gs \in GS_b} p^{GSch}_{gs,t} - \sum_{dr \in DR_b} p^{DRpyb}_{dr,t} = D_{b,t} - LS_{b,t} \tag{2}$$

Demand response borrowing acts as a load reduction (generation-side) and payback as additional load.

### Storage constraints

We add storage time-coupling constraints (`constraints.jl:103-110`, `storConservationStart` / `storConservation`):

$$e_{s,1} = \eta^{Scarry}_s\, e_{s,0} + \eta^{Sch}_s\, p^{Sch}_{s,1} - \frac{p^{Sdch}_{s,1}}{\eta^{Sdch}_s} \qquad \forall s \in S$$

$$e_{s,t} = \eta^{Scarry}_s\, e_{s,t-1} + \eta^{Sch}_s\, p^{Sch}_{s,t} - \frac{p^{Sdch}_{s,t}}{\eta^{Sdch}_s} \qquad \text{for } t = 2,\ldots,N, \; \forall s \in S$$

And for generator-storage units (`constraints.jl:115-122`, `genstorConservationStart` / `genstorConservation`):

$$e_{gs,1} + s_{gs,1} = \eta^{GScarry}_{gs}\, e_{gs,0} + \eta^{GSch}_{gs}\, p^{GSch}_{gs,1} - \frac{p^{GSdch}_{gs,1}}{\eta^{GSdch}_{gs}} + p^{inflow}_{gs,1} \qquad \forall gs \in GS$$

$$e_{gs,t} + s_{gs,t} = \eta^{GScarry}_{gs}\, e_{gs,t-1} + \eta^{GSch}_{gs}\, p^{GSch}_{gs,t} - \frac{p^{GSdch}_{gs,t}}{\eta^{GSdch}_{gs}} + p^{inflow}_{gs,t} \qquad \text{for } t = 2,\ldots,N, \; \forall gs \in GS$$

Additionally, we add the state of charge constraints for generator-storage units when activated (`constraints.jl:428-429`, `hydroFinalSOCLimit`, only for categories listed in `hydro_parameters["final_soc_constraint"]`):

$$e_{gs,N} \ge e_{gs,0} - e^{slack}_{gs} + p^{inflow}_{gs,1} - p^{inflow}_{gs,2} \qquad \forall gs \in GS$$

The inflows in timesteps 1 and 2 are explicitly included to capture the step when all the SoC is coming from inflows in the first timestep to set a more realistic initial SoC — this is a workaround since PRAS doesn't support initial SoC yet.

### Demand Response constraints

For all DR that is not allowed to "pre-charge" we enforce limits on the energy state of charge (`constraints.jl:159,162`, `drsPaybackBeforeBorrowingDSP` / `...EV`, controlled by `DER_parameters["DSP_payback_before_borrowing"]` / `["EV_payback_before_borrowing"]`):

$$0.0 \le e^{DR}_{dr,t} \qquad \forall dr \in DR^{no\,pre\text{-}charge}, t \in T$$

And then ensure that energy conservation across timesteps (adjusted with the interest rate $r_{dr}$) (`constraints.jl:167-172`, `drsConservationStart` / `drsConservation`):

$$e_{dr,1} = (1 + r_{dr})\, p^{DRbrw}_{dr,1} - p^{DRpyb}_{dr,1} \qquad \forall dr \in DR$$

$$e_{dr,t} = e_{dr,t-1} + (1 + r_{dr})\, p^{DRbrw}_{dr,t} - p^{DRpyb}_{dr,t} \qquad \text{for } t = 2,\ldots,N, \; \forall dr \in DR$$

Finally, all borrowed energy has to be repaid by the end of the optimisation window (`constraints.jl:175`, `drsPaybackComplete`):

$$e^{DR}_{dr,N} = 0 \qquad \forall dr \in DR$$

> [!NOTE]
> Since the interest of DSP units is set to $r_{dr} = -1$ during parameter updates (see the parameter note above), the conservation and terminal constraints are effectively only binding for EV units: DSP borrowing represents pure load reduction without payback.

Additionally, we enforce maximum energy activation limits within each consecutive time-window of length $w$ (`constraints.jl:227` for DSP, `:240` for EV; `drsMaxEnergyDSP` / `drsMaxEnergyEV`):

$$\sum_{t=T-w+1}^{T} p^{DRbrw}_{dr,t} \le \frac{\bar{E}^{maxBrwHrs}_{dr}}{w} \sum_{t=T-w+1}^{T} \bar{P}^{DRbrw}_{dr,t} \qquad T \in \{w, 2w, \ldots\}, \; \forall dr \in DR$$

as well as one constraint per window that accounts for energy already borrowed before the start of the current optimisation window (`constraints.jl:228,241`, `drsMaxEnergyDSP_withBorrowBefore` / `drsMaxEnergyEV_withBorrowBefore`):

$$\sum_{t=1}^{N} \mathbb{1}^{brwBefore}_{dr,t}\; p^{DRbrw}_{dr,t} + e^{brwBefore}_{dr} \le \frac{\bar{E}^{maxBrwHrs}_{dr}}{N} \sum_{t=1}^{N} \bar{P}^{DRbrw}_{dr,t} \qquad \forall dr \in DR$$

This reflects AEMO practices to limit the energy per day that can be activated through DSP. For DSP, these constraints are only applied to units in the configured price bands (`DER_parameters["DSP_limit_energy_per_window"]["limits_on_price_bands"]`, `constraints.jl:205-220`).

> [!NOTE]
> A payback-time constraint enforcing payback within a time window after each borrowing (`add_constraints_demandResponse_paybackTime`, `constraints.jl:257-280`) is implemented but currently not enabled in `build_operation_model` (`model/core.jl:114`).

### Generator constraints

We add the following ramping constraints (`constraints.jl:333-340`, `rampUp` / `rampDown`, only for generators with $R^{up}_g < \bar{P}_g$ resp. $R^{dn}_g < \bar{P}_g$):

$$p_{g,1} - p_{g,0} \le R^{up}_g + \underline{P}_{g}\, \delta^{stup}_{g,1} \qquad \forall g \in G$$

$$p_{g,t} - p_{g,t-1} \le R^{up}_g + \underline{P}_{g}\, \delta^{stup}_{g,t} \qquad \text{for } t = 2,\ldots,N, \; \forall g \in G$$

$$p_{g,0} - p_{g,1} - \delta^{fail}_{g,1}\, \bar{P}_g \le R^{dn}_g + \underline{P}_{g}\, \delta^{shdw}_{g,1} \qquad \forall g \in G$$

$$p_{g,t-1} - p_{g,t} - \delta^{fail}_{g,t}\, \bar{P}_g \le R^{dn}_g + \underline{P}_{g}\, \delta^{shdw}_{g,t} \qquad \text{for } t = 2,\ldots,N, \; \forall g \in G$$

The term $\delta^{fail}_{g,t}\, \bar{P}_g$ relaxes the ramp-down constraint when a generator fails, so that a forced outage (an instantaneous drop to zero output) does not make the problem infeasible. The same mechanism is used to disable ramping into the deactivated padding timesteps of a short final window (`update/updateParameters.jl:210-216`).

And unit commitment constraints for all generators that have $T^{up/dn}_g > 0$ or $\underline{P}_{g} > 0$ (`constraints.jl:357-366`, `stup_shdw` / `stup_shdw_check`):

$$\delta^{stup}_{g,1} - \delta^{shdw}_{g,1} = \delta^{on}_{g,1} - \delta^{on}_{g,0} \qquad \forall g \in G^{UC}$$

$$\delta^{stup}_{g,t} - \delta^{shdw}_{g,t} = \delta^{on}_{g,t} - \delta^{on}_{g,t-1} \qquad \text{for } t = 2,\ldots,N, \; \forall g \in G^{UC}$$

$$\delta^{stup}_{g,t} + \delta^{shdw}_{g,t} \le 1 \qquad \forall t \in T, g \in G^{UC}$$

and add min up/down time constraints (`constraints.jl:395-401`, stored as `m[:minUpTime]` / `m[:minDownTime]`):

$$\delta^{on}_{g,t} \ge \sum_{\tau = \max(1,\, t - \lceil T^{up}_g \rceil + 1)}^{t} \left( \delta^{stup}_{g,\tau} - \delta^{fail}_{g,\tau} \right) + \sum_{\tau = N - \lceil T^{up}_g \rceil + t + 1}^{N} \left( \delta^{stup,bfr}_{g,\tau} - \delta^{fail,bfr}_{g,\tau} \right) \qquad \forall t \in T, g \in G^{UC}$$

$$\delta^{on}_{g,t} \le 1 - \sum_{\tau = \max(1,\, t - \lceil T^{dn}_g \rceil + 1)}^{t} \delta^{shdw}_{g,\tau} - \sum_{\tau = N - \lceil T^{dn}_g \rceil + t + 1}^{N} \delta^{shdw,bfr}_{g,\tau} \qquad \forall t \in T, g \in G^{UC}$$

The second sum in each constraint carries the start-up/shut-down history from before the start of the optimisation window, so that minimum up/down times are respected across the rolling horizon. In the min-up-time constraint, a failure ($\delta^{fail}_{g,\tau} = 1$) cancels the obligation of a recent start-up to stay online, so that forced outages remain feasible.

If the generators are not affected by UC constraints, we assume the generator as available: $\delta^{on}_{g,t} = 1 \; \forall t \in T, g \in G^{no\,UC}$ (`constraints.jl:372-373`, `gon_fix`).

With this we follow the formulation in [5]. For an exact solution, we may set all $\delta$-variables to binary, however for increased computational speed, we relax the variables to be within $[0, 1]$ and round the resulting on/off status (`model/variables.jl:44-57`, controlled by `genOpDetails.binary`; the conservative rounding happens in `analysis/getResults.jl`). This allows to represent the capacity constraints that the system may face in greater detail than with economic dispatch alone.

## Additional model features

- **Reserves via demand inflation** — `addReserve!(sys)` (`update/addReserve.jl`) adds the ISP 2024 minimum reserve requirements to the regional loads (distributed within each area proportionally to peak load) rather than adding an explicit reserve variable or constraint. `run_operation_model(...; include_reserve_run=true)` performs a two-pass solve per rolling-horizon window: first with the reserve-inflated system, then the resulting commitments are fixed as lower bounds on $\delta^{on}$ (`set_lower_bound.(m[:gon], gons)`) and the window is re-solved with the actual demand (`model/core.jl:221-244`). On infeasibility, the reserve-based bounds are relaxed and the window re-solved.
- **VPP disabling** — if `DER_parameters["VPP_flexibility"] = false`, the state of charge of VPP-category storages is fixed to zero (`constraints.jl:291-307`).
- **Rolling horizon / reoptimisation mechanics** — the model is built once as a ParametricOptInterface model; between windows and Monte-Carlo samples only parameter values are updated (`update/updateParameters.jl`), including feasibility reconciliation of the initial commitment state (`update/update_utils.jl`). The reoptimisation module (`reoptimisation/`) re-dispatches around shortfall events per outage sample with imperfect (default) or perfect foresight of outages.
- **Short final windows** — when the optimisation window extends past the end of the input data, the remaining timesteps are deactivated by setting demand and capacities to zero and disabling ramping into the padding (`update/updateParameters.jl`).
